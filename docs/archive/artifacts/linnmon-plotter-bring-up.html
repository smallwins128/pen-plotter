Why the pen lift never worked

Stock GRBL 1.1 does put a PWM signal on D11. It is the wrong PWM, and no wiring change and no G-code sender can make it right. From grbl/cpu_map.h:

// Prescaled, 8-bit Fast PWM mode.
// #define SPINDLE_TCCRB_INIT_MASK   (1<<CS20)               // no prescaler -> 62.5 kHz
// #define SPINDLE_TCCRB_INIT_MASK   (1<<CS21)               // 1/8   -> 7.8 kHz  (v0.9)
// #define SPINDLE_TCCRB_INIT_MASK   ((1<<CS21) | (1<<CS20)) // 1/32  -> 1.96 kHz
#define SPINDLE_TCCRB_INIT_MASK      (1<<CS22)               // 1/64  -> 0.98 kHz  <-- DEFAULT

980 Hz. That is a 1.02 ms frame. An RC servo needs a 50–60 Hz frame with a 1–2 ms pulse inside it — the whole frame is shorter than the pulse the servo is looking for. It never sees a decodable command, so it sits at an endpoint, buzzes, or twitches. There is no S value that fixes this.

The timer prescaler is set in firmware, which is why the fix has to be a re-flash. One line changes the frame to 61 Hz; two more map the S range onto 0.5–2.5 ms. After that, everything else is tuning.

Corrections to the notes

Both documents — the handoff and the research summary — are mostly right. These eight points are not, and most of them cost hardware or hours.

  1. A sender cannot substitute for the firmware change

    “Setup methods: custom firmware… or G-code senders: use GRBL-Plotter, which automatically converts Z moves into the spindle speed commands the servo requires.”

    These are not alternatives. GRBL-Plotter converts Z moves into M3 S commands, which is genuinely useful — but the pulse train those commands produce is still 980 Hz. The firmware edit is mandatory; the sender choice is a convenience on top of it.

    The one real no-reflash path is external hardware: a small MCU or servo driver board that reads D11's duty cycle and re-emits proper servo pulses. More parts, more wires, worse than four lines of C.

  2. D11 and D12 are two different pins with two different jobs

    “Connect the servo's control wire to the PWM pin, commonly found on the Z-Endstop or Spindle (SpnEn) pin header.”

    On GRBL 1.1 with VARIABLE_SPINDLE — the default — these are swapped relative to the shield silkscreen. The servo signal goes on the header marked Z endstop (D11). The header marked SpnEn (D12) is what GRBL reads as the Z limit switch. Guessing between them means driving a servo signal into a limit input, or shorting an output to ground. Full map in phase 2.

  3. M5 is not “pen up”

    “Software interprets spindle speed commands (M3 / M5) to position the servo horn up or down.”

    M5 and S0 both call spindle_stop(), which clears COM2A1 and disconnects the pin entirely. The servo stops receiving pulses, goes slack, and the pen drops. M5 is not a position — it is an absence of signal.

    Use M3 S<up> for up and M3 S<down> for down. Never M5 mid-job.

  4. The S range is $30, not a universal 0–1000

    “…the correct spindle speed commands (S0–S1000) required by the servo.”

    S0–S1000 is one common setup, not a rule. Here $30=180, so the range is S0–S180 and S reads roughly as degrees. What the endpoints of that range mean in microseconds is set by SPINDLE_PWM_MIN_VALUE / MAX_VALUE in firmware — the pair only makes sense together.

  5. 6 V is too much for a 9 g servo

    Handoff: “buck set to ~6 V”.

    SG90 and MG90S class servos are 4.8–6 V parts and run hot and jittery at the top of that. Set the buck to 5.0–5.5 V. 6.0 V is only appropriate for an MG996R-class servo rated 4.8–7.2 V. Set it with the servo disconnected and a meter on the output, before it ever sees the load.

  6. Homing cannot work until config.h changes

    The handoff has homing off and treats it as an option for later. It is not optional and it will not work as shipped: GRBL's default homing cycle homes Z first, and this machine has no Z switch — so $H can only ever end in ALARM:9. This is a one-line edit (phase 1), and homing is what makes work zero survive a reset (phase 7), which solves the “opening the port resets the Arduino” problem outright.

  7. M2 is not dangerous — it resets your modal state

    Handoff: “Avoid M2 at end of file — it triggered a controller reset in testing.”

    Right conclusion, wrong reason. Program end runs spindle_set_state(SPINDLE_DISABLE, 0) — the pen drops — and then resets the modal state: back to G90, back to G54, plane to G17, and feed rate to 0. Anything streamed afterwards throws error:22. It looks like a reset because everything you set up is gone. Still: end the file after the last move.

  8. $1=25 lets the gantry drift; $10=10 is a 0.9-ism

    $1=25 de-energises the steppers 25 ms after motion stops — which is every pen-change dwell — and belt tension can then drag the gantry. Use $1=255 (never disable). The motors will run warm; that is correct.

    $10 in GRBL 1.1 has only two meaningful bits: 1 = machine position, 2 = buffer state. $10=10 is a leftover from 0.9 and sets a bit that no longer exists. Use $10=3.

Right in the notes, worth keeping

The $100=80 derivation (200 × 16 ÷ 40); $3=1 as the only place mirroring gets fixed; $5=1 because the switches are NC; grounding D12; refusing hard limits; the two-pass homing behaviour being normal; the negative machine coordinates being normal; and not powering the servo from the Arduino's 5 V rail. All correct, all load-bearing.

Safety and power-up order

  • Never plug or unplug a stepper while the shield is powered. The single most common way to kill an A4988.
  • USB first, then the 24 V PSU. GRBL boots and drives the enable line and D11 to a known state before the drivers and servo are energised. Power down in reverse.
  • The servo twitches on every Arduino reset — and opening the serial port is a reset. Make sure the carriage cannot jam or stab the bed at either servo extreme.
  • The LRS-350 has mains on its input terminals. Cover them.

Firmware: four edits

Use gnea/grbl v1.1h. Not bdring/Grbl_Pen_Servo — that is a fork of GRBL 0.9, and it costs you $J= jogging, real-time feed and rapid overrides, the 1.1 status format, and the error/alarm tables every modern sender and troubleshooting page assumes.

Install by copying the inner grbl/ folder — the one containing grbl.h — to ~/Documents/Arduino/libraries/grbl/. grbl.h: No such file or directory always means it is nested one level too deep.

Edit 1 — servo frame rate cpu_map.h

// 1/1024 prescaler -> 61.0 Hz frame, 64 us per PWM count. RC servo compatible.
#define SPINDLE_TCCRB_INIT_MASK   ((1<<CS22) | (1<<CS21) | (1<<CS20))

16 MHz ÷ 1024 ÷ 256 = 61.04 Hz, a 16.4 ms frame, and one OCR count = 64 µs.

Edit 2 — map S onto 0.5–2.5 ms cpu_map.h

#define SPINDLE_PWM_MAX_VALUE     39   // 39 * 64us = 2496 us   (was 255)
#ifndef SPINDLE_PWM_MIN_VALUE
  #define SPINDLE_PWM_MIN_VALUE   8    //  8 * 64us =  512 us   (was 1)
#endif

SPINDLE_PWM_MAX_VALUE has no #ifndef guard, so it must be edited here — setting it in config.h silently does nothing. Its “Don't change” comment refers to the timer TOP value; lowering the mapping ceiling is exactly what we want.

Edit 3 — homing cycle without a Z switch config.h

// was: HOMING_CYCLE_0 (1<<Z_AXIS) / HOMING_CYCLE_1 ((1<<X_AXIS)|(1<<Y_AXIS))
#define HOMING_CYCLE_0 (1<<X_AXIS)
#define HOMING_CYCLE_1 (1<<Y_AXIS)
// #define HOMING_CYCLE_2

Sequential rather than simultaneous, so during bring-up you can watch one axis at a time.

Edit 4 — single-axis homing config.h

#define HOMING_SINGLE_AXIS_COMMANDS // Default disabled. Uncomment to enable.

Gives you $HX and $HY. A switch wired backwards then drives one motor into a stop instead of two.

Optional but worth it: set GRBL_VERSION_BUILD "20260823-servo" in grbl.h, so $I tells you definitively which firmware is on the board instead of you inferring it from servo behaviour.

Before you upload

Physically remove the CNC shield. D0/D1 are the serial lines, and you do not want the steppers live while the board resets. Flashing wipes EEPROM — settings and your G10 L20 work zero. Restore both after.

Verify the flash

Send $I. Expect:

[VER:1.1h.20260823-servo:]
[OPT:VH,15,128]

V means VARIABLE_SPINDLE is compiled in. Without it, D11 is not a PWM pin at all and the Z limit moves back onto D11 — stop and fix that before wiring anything. H confirms edit 4. The build string confirms edits 1–3 are in this binary; OPT does not report the timer change, which is why the version stamp earns its keep.

Gate

$I returns V and H in the OPT string, and your own build stamp in the version.

The pin map

This is where the confusion lives. Compiling with VARIABLE_SPINDLE swaps the Z-limit and spindle pins so GRBL can reach the hardware PWM on D11:

#ifdef VARIABLE_SPINDLE // Z Limit pin and spindle enabled swapped to access hardware PWM on Pin 11.
  #define Z_LIMIT_BIT   4 // Uno Digital Pin 12
#else
  #define Z_LIMIT_BIT   3 // Uno Digital Pin 11
#endif

Wiring

Endstops

Both harvested Ender switches are NC — normally closed: closed at rest, open when pressed. Two wires each, signal and GND, polarity irrelevant. X to D9, Y to D10.

GRBL enables an internal pull-up on every limit pin. With $5=0 a LOW pin reads as triggered — which for an NC switch is its resting state, so GRBL would believe both switches are permanently pressed. $5=1 inverts that and is required. Route the switch wiring away from the stepper cables; NC's one genuine virtue is that a broken wire looks like a pressed switch, so it fails loud.

D12 — the pin that must be grounded

$5=1 inverts all limit pins, Z included. D12 has nothing on it, the pull-up holds it HIGH, and HIGH-when-inverted means triggered — that is the phantom Pn:Z that sits in the status report forever.

D12 (SpnEn header)  ──►  any shield GND pin

One jumper wire. Required before hard limits are even thinkable, harmless otherwise. If you would rather not have the wire, compiling #define INVERT_LIMIT_PIN_MASK (1<<Z_LIMIT_BIT) inverts Z alone — but the wire is simpler.

Servo

SIGNAL (yellow/orange, outer)  ──►  D11 = "Z endstop" header signal pin
V+     (red, MIDDLE wire)      ──►  buck VOUT+   (5.0–5.5 V)
GND    (brown/black, outer)    ──►  buck VOUT−  AND a shield GND pin
  • The middle wire is always power. Get it wrong and the servo dies instantly.
  • Set the buck voltage with the servo disconnected, meter on the output.
  • 470–1000 µF electrolytic across V+ and GND, physically at the servo. Not optional in practice — the lift current spike is what causes the random resets.
  • Never power the servo from the Arduino or shield 5 V rail. A stalled 9 g servo pulls ~700 mA and the regulator browns out mid-plot.
  • The common ground is real via the shared PSU, but keep the explicit brown-to-shield-GND link anyway — it is the signal return path, and without it the servo jitters.
  • Still jittering? Check whether your shield has a filter capacitor fitted across that endstop pin — some V3.51 clones do, and it rounds off the servo pulse. Remove it.

Power chain

Mean Well LRS-350-24  (24 V, 14.6 A)
  ├─► CNC Shield V+ / GND          (steppers)
  └─► LM2596 buck @ 5.0–5.5 V  ──► servo  (+ bulk cap at the servo)

24 V is inside the A4988's 35 V ceiling and gives the Ender motors good top speed, but A4988s at 24 V run hot. Heatsinks on all three, and a fan if the electronics are enclosed. Random mid-plot stalls that are not mechanical are thermal shutdown until proven otherwise.

Optional, cheap, worth it

An abort button on A0 to GND, so Ctrl-X over serial is not your only emergency stop. And 10 µF between RESET and GND suppresses the DTR auto-reset so opening the port stops resetting the controller — remove it to flash. Phase 7 explains why this matters much less once homing is on.

Gate

? at rest shows no Pn: field at all. Pressing X by hand makes Pn:X appear and releasing makes it vanish; same for Y.

4

Drivers and mechanics

A4988 current

The Ender 42-34s are ~0.84 A/phase. Set each driver's Vref with a meter on the pot, motor connected, board powered, motor idle:

Vref = I_target × 8 × R_sense

R_sense = 0.100 Ω  →  0.84 A ≈ 0.67 V
R_sense = 0.050 Ω  →  0.84 A ≈ 1.34 V

Check which sense resistors your boards actually have — marked R100 or R050 beside the chip. Getting it backwards is a factor-of-two current error. Start at ~80 % of those figures. A plotter needs very little torque, and running cool is worth more than headroom.

Microstepping

1/16 on the V3 shield = all three jumpers fitted under each driver. All three drivers identical, or the two X motors fight each other. $100 = 200 × 16 ÷ (20 × 2) = 80 steps/mm — confirmed by test T3.

Squaring the dual-X gantry

Two motors, one axis, one limit switch. Homing finds one end; it cannot square the beam. If the gantry is racked, it stays racked.

Before each session: power off so both motors are de-energised, push the gantry gently against a hard mechanical reference at both ends until it seats square, then power up. With $1=255 the motors stay energised from then on and it holds.

If racking becomes a recurring annoyance, the real fix is a second X switch and a controller that can auto-square — which the Uno cannot do while also driving the servo. That is an ESP32/FluidNC upgrade, not a GRBL-on-Uno one.

Pen holder — the biggest determinant of line quality

  • The pen should be spring-loaded or gravity-floating, with the servo only lifting it.
  • Tune pen-down so the arm travels slightly past the touch point, so the pen floats on its spring. A servo pressing the pen into the paper stalls, buzzes, draws current, and gives you line weight that varies with how flat the bed is.
  • Aim for 25–40° of servo travel between up and down. Much less and the coarse S resolution becomes visible; much more and the lift is slow.
  • Set the horn on the spline at mid-travel before tightening, so S90 is roughly centre.
Gate

Gantry seats square by hand, drivers warm rather than hot after a few minutes enabled, pen holder floats on its spring.

Leave exactly as they are

  • $3=1 — inverts X. Mirroring is fixed here and never by flipping G-code files.
  • $5=1 — required by the NC switches.
  • $21=0 — hard limits stay off, permanently. NC switches on unshielded wire beside stepper cables, plus a pin-change interrupt, equals ALARM:1 at random. Homing plus soft limits gives the same protection without the false trips.
  • $23=2 — Y homes negative, X positive: home corner front-right, $H drives +X and −Y.
  • $30=180, $31=0 — maps S linearly across the servo's pulse range. Never change one without the other.
  • $32=0 — laser mode off, and it must stay off. Laser mode applies S changes during motion without draining the planner, so the pen would lift somewhere in the middle of a line instead of at its end.

Why machine coordinates go negative — and why that is right

X homes positive, so it ends at ≈ −3 mm with travel running to −$130. Y homes negative, so it ends at ≈ −($131−3) with travel running up to 0. The workspace is therefore the box X ∈ [−$130, 0], Y ∈ [−$131, 0] — all negative, which is exactly what GRBL's soft-limit checker requires (“assumes the workspace volume is in all negative space”, limits.c).

A drawing authored in Quadrant I from a work zero at the paper's bottom-left runs toward (0, 0) — inside the box the whole way.

Rule this imposes on generated G-code

No Z words. At all. Soft limits check every axis including the unhomed Z, so a single G0 Z5 throws ALARM:2 and aborts the job. The pen is M3 S<n>; there is no Z axis on this machine.

The test ladder

Run T0 through T6 in order. Each only means something if the previous passed.

Before any G-code — read the pins

Send ?. At rest, with nothing pressed, Pn: should be absent entirely.

  • Pn:Z present → D12 is not grounded.
  • Pn:XY present → $5 is wrong for NC switches, or the switches are on the wrong pins.
  • Press each switch by hand and confirm the flag appears and clears. Do this before homing — a switch that does not toggle here will drive the gantry into the frame at 500 mm/min.

T0 — servo only, no motion

Run tools/servo_sweep.py: u/d nudge by one PWM count, a number jumps, q parks and quits. Find pen-up (clears the paper by 3–5 mm, no more) and pen-down (touching, holder's spring taking the pressure, servo not straining). Buzzing means you have gone past the servo's mechanical stop or you are pressing into the bed — back off.

Then run T0_servo_only.gcode: five clean cycles, no motor motion, no buzzing, no board resets.

If the servo does not move at all, or slams to one end and stays: the timer edit did not take. Back to phase 1.

pwm = floor(S × 31 / 180) + 8, pulse = pwm × 64 µs. One PWM count is about 6 units of S — S70 and S73 are the same pulse. Step S by 6 or more; anything finer is noise, and fine pen-height adjustment belongs in the holder, not the S value.

T1 — motion, pen up

Four laps of a 50 mm square in the air, returning to work zero. Both X motors turning together, no buzzing, no missed corners. Mark the start point and confirm it lands back on it.

T2 — first line on paper

One 50 mm square, pen down. Corners square, line closes cleanly on itself.

T3 — calibrate steps/mm

A 100 mm line along each axis. Measure with calipers:

$100_new = $100_old × (100 / measured_X)
$101_new = $101_old × (100 / measured_Y)

More than ~2 % off means a 16-tooth pulley, a missing microstep jumper, or belt slip. Find the cause rather than fudging the number.

T4 — pen lift reliability

Eight 10 mm dashes with a lift between each. The test that matters most. Every dash the same length and weight, gaps genuinely blank. Tails or dots in the gaps mean the dwell is too short — raise G4 P0.20 to P0.30.

T5 — acceleration tuning

A fast zigzag returning to origin. Raise $120/$121 together — 200 → 300 → 400 — re-running after each. The first value that loses position is your ceiling; back off 30 %. Then do the same for $110/$111 if you want more speed: the Uno can push far more step rate than this machine needs, so mechanics will be the limit, not GRBL.

T6 — squareness

A 100 mm square with both diagonals. Measure them — equal (141.4 mm) means the gantry is square. Unequal means the beam is racked; back to phase 4.

Homing, last

Only after T0–T6 pass, and with a hand on the USB cable: $HX, watch it. Then $HY. Then $H. Each axis moves twice — fast seek, pull off, slow locate, pull off. That is N_HOMING_LOCATE_CYCLE doing its job, not a bug.

Then set $130/$131 to the travel you measured, and only then $20=1.

Gate

T0–T6 all pass, homing repeats to the same spot, $20=1 and $22=1 are on.

7

Running plots

Set work zero once — it lives in EEPROM

G10 L20 P1 writes the G54 offset to EEPROM, so it survives resets, power cycles and serial reconnects. Homing gives it a repeatable machine origin to be measured from. Together they retire the “opening the port resets the Arduino and I lose my position” problem entirely.

First time on a new paper position:

python3 plot.py --port <port> --send '$H'                 # establish machine origin
python3 plot.py --port <port> --jog X-40                  # jog to the paper's bottom-left
python3 plot.py --port <port> --send 'G10 L20 P1 X0 Y0'   # store work zero

Every session after that:

python3 plot.py --port <port> --send '$H'      # that's the whole ritual
python3 plot.py --port <port> --send '$#'      # optional: confirm G54 is still there
python3 plot.py --port <port> plot.gcode

For jogging, prefer GRBL 1.1's jog command over G0: $J=G91 G21 X10 F1000. It leaves modal state alone, respects soft limits, and is cancellable mid-move.

File conventions

G21          ; mm                    | G-code preamble
G90          ; absolute
G94          ; units per minute
M3 S160      ; pen up
G4 P0.30     ; let it get there
...
M3 S160      ; pen up                 | postamble
G4 P0.30
G0 X0 Y0     ; back to work zero
  • No M2 / M30 — it drops the pen and resets feed rate to 0, so everything after throws error:22. Just end after the last move.
  • No mid-file M5 — it disconnects the PWM pin and the servo goes slack.
  • No Z words — soft limits will abort the job.
  • Feeds at F2000 or below while $110/$111 are 2000; anything higher is silently clamped, so time estimates must assume 2000 mm/min.
  • Prefer G90 absolute for long plots — a dead stream can be resumed from a line number. G91 cannot.

Streaming

Use plot.py over UGS. The UGS failures here were real: desyncs, silent mid-job cancels, and — the nasty one — iCloud placeholder files that had not downloaded, which UGS streams as a truncated file and then reports “done”.

  • Close UGS first. One program per serial port.
  • ok means accepted into the planner buffer, not executed. Motion can be in flight for seconds after the last ok. Wait for Idle before concluding anything.
  • Check status inside the same connection — a separate invocation resets the board.

Reading the status line

<Idle|MPos:-3.000,-197.000,0.000|Bf:15,128|FS:0,0|WCO:-40.000,-150.000,0.000>
  • State: Idle / Run / Jog / Hold / Alarm / Home / Door / Check.
  • WCO is the G54 offset, emitted periodically so a sender can convert between machine and work position.
  • Bf:15,128 — planner blocks free, RX bytes free. If the first number sits at 15 while streaming, the sender is not keeping the buffer fed and the machine is stopping between segments.
  • Pn: appears only when something is triggered. Absent is what you want.

Gotchas worth keeping in your head

  • $22=1 makes GRBL boot into Alarm and refuse everything including jogging until $H or $X. By design, and thoroughly confusing if you forget.
  • Re-flashing wipes EEPROM — settings and your work zero.
  • With a working pen lift, multi-stroke art no longer needs single-stroke chaining. Plot the original file; the visible connectors go away.
